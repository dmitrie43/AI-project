# Лекция: Вероятность, Softmax и Temperature (Фаза C)

**Для кого:** после фазы B (метрики).  
**Цель:** без паники объяснять бизнесу «модель не уверена», softmax и temperature в LLM.  
**Глубина:** интуиция, не теорвер из вуза.

---

## 0. Зачем эта лекция

В GenAI вы постоянно встречаете:

- «вероятность класса 0.82»;
- softmax в классификаторах;
- `temperature=0.2` / `temperature=1` у LLM.

Нужно понимать не интегралы, а:

1. что значит число от 0 до 1;
2. как сырые баллы модели превращаются в «доли»;
3. почему temperature меняет «смелость» ответа.

---

## 1. Вероятность 0…1

**Вероятность** — число от 0 до 1 (или 0%…100%), насколько исход ожидаем.

| Значение | Смысл |
|----------|--------|
| 0 | почти невозможно |
| 0.5 | fifty-fifty |
| 1 | почти наверняка |
| 0.9 | сильно ожидаем, но не гарантия |

Важно: **0.9 ≠ «точно случится»**.  
Из 100 похожих случаев ожидаем около 90 — иногда будет 85, иногда 94.

### Сумма исходов = 1

Если исходы **полные и не пересекаются** (тикет либо open, либо resolved, либо pending — ровно один статус):

\[
P(\text{open}) + P(\text{resolved}) + P(\text{pending}) = 1
\]

Аналогия Laravel: в `enum` статуса ровно одно значение. Доли «уверенности» модели по статусам должны в сумме давать 100%.

Если модель выдала 0.7 + 0.5 + 0.2 = 1.4 — это ещё не вероятности, а сырые числа (их как раз нормализует softmax).

---

## 2. Независимость «на пальцах»

Два события **независимы**, если знание об одном не меняет ожидание другого.

- Бросок монеты и погода за окном — независимы.
- «Тикет про VPN» и «в тексте есть слово vpn» — **зависимы**.

В LLM/ML мы почти всегда имеем дело с **зависимыми** признаками.  
Формулу «P(A и B) = P(A)·P(B)» для пилота помнить не обязательно; важно не путать «два раза подряд орёл» с поломкой монеты (см. задачу C3).

---

## 3. Матожидание ≈ среднее

**Математическое ожидание** на пальцах — «средний выигрыш / среднее значение», если повторить ситуацию много раз.

Пример: время ответа API иногда 1с, иногда 3с, иногда 2с.  
Матожидание ≈ среднее по многим замерам.

Для фазы C достаточно: *ожидание ≈ то, к чему стремится среднее при большом числе повторов*.

---

## 4. Дисперсия / разброс (интуиция)

Два сервиса со **средним** latency 2с:

| Сервис | Типичные значения | Ощущение |
|--------|-------------------|----------|
| A | 1.9, 2.0, 2.1 | стабильный |
| B | 0.3, 2.0, 5.5 | средний тот же, разброс огромный |

**Дисперсия / разброс** — насколько значения гуляют вокруг среднего.  
Для прода позже важнее p95 (фаза D); здесь идея: *одно среднее не описывает риск*.

Связь с LLM: высокая temperature → ответы более «разбросанные» (разнообразные, менее предсказуемые).

## 5. Softmax — из сырых чисел в вероятности

Модель часто сначала выдаёт **logits** — сырые баллы классов, не вероятности:

```
urgent:     2.0
normal:     1.0
low:        0.1
```

Проблемы сырых чисел:

- могут быть любыми (отрицательными, >1);
- сумма не 1;
- сравнивать «на глаз» можно, но в продукт удобнее доли.

**Softmax** превращает logits в вероятности:

1. возвести каждое в «экспоненту» \(e^{x}\) (усилить разницу: большее становится ещё больше);
2. поделить каждое на сумму всех — чтобы сумма стала 1.

Интуиция без калькулятора:

- у кого logit больше — у того вероятность больше;
- разрыв усиливается: 2.0 сильно обгоняет 0.1.

### Мини-пример (как в C1)

Logits: `[2, 1, 0.1]`

Относительно (калькулятор):

| Класс | logit | e^logit (примерно) | после нормировки |
|-------|-------|--------------------|------------------|
| A | 2.0 | 7.39 | ≈ 0.66 |
| B | 1.0 | 2.72 | ≈ 0.24 |
| C | 0.1 | 1.11 | ≈ 0.10 |
| | | сумма ≈ 11.22 | сумма = 1 |

Победитель — **класс A** (~66%).

Аналогия Laravel: три кандидата в `match`, softmax — как нормализованные «голоса», в сумме 100%.

## 6. Temperature — подробно

### 6.1. Где она живёт

LLM пишет текст **по одному токену** (кусок слова / слово).

На каждом шаге у модели есть сырые баллы (logits) по словарю: насколько «логичен» каждый следующий токен.  
Из них softmax делает вероятности, затем **случайно** (с учётом вероятностей) выбирается следующий токен.

**Temperature** — параметр *до* softmax: logits делят на \(T\).  
Она не «греет железо», а меняет, насколько резко отличаются вероятности.

Аналогия Laravel: у вас weighted random — выбрать шаблон ответа A/B/C с весами.  
Temperature = насколько сильно раздувать разницу весов перед выбором.

### 6.2. Один числовой пример

Допустим, три кандидата следующего токена (упрощённо):

| Токен | logit |
|-------|-------|
| «пароль» | 2.0 |
| «логин» | 1.0 |
| «кот» | 0.1 |

**При T = 1** (как в §5): примерно 66% / 24% / 10%.  
Чаще выпадет «пароль», но «логин» ещё бывает.

**При T = 0.5** (низкая): logits делим на 0.5 → становятся `[4, 2, 0.2]`.  
После softmax разрыв ещё сильнее: «пароль» может стать ~88%, «логин» ~12%, «кот» ~1%.  
Почти всегда один и тот же безопасный путь.

**При T = 2** (высокая): logits делим на 2 → `[1, 0.5, 0.05]`.  
Распределение **плоскее**: шансы ближе друг к другу.  
«кот» выпадает заметно чаще → текст неожиданнее и чаще ломается по смыслу.

Интуиция:

| Temperature | Распределение | Поведение текста |
|-------------|---------------|------------------|
| → 0 | очень острое | почти всегда top-1 токен, стабильно |
| 1 | обычное | баланс |
| ↑ | плоское | разнообразие, хаос, риск бреда |

### 6.3. Temperature ≈ 0

На практике `temperature=0` (или очень маленькая):

- выбор **жадный**: почти всегда самый вероятный токен;
- один и тот же промпт → очень похожие ответы (часто почти одинаковые);
- хорошо: код, JSON, SQL, извлечение полей, ответы по runbook/RAG «строго по фактам»;
- плохо: мозговой штурм, разные варианты формулировок, креатив.

Для внутреннего пилота поддержки обычно начинают с **0 … 0.3**.

### 6.4. Temperature = 1

- «заводская» шкала без сжатия/растяжения logits;
- ответы живее, запуски одного промпта сильнее отличаются;
- выше шанс полезной вариативности **и** галлюцинаций.

### 6.5. Высокая temperature (1.2–2.0)

- модель чаще берёт редкие токены;
- стиль разнообразнее;
- для фактологических задач обычно вредно: выдуманные API, неверные шаги VPN, сломанный JSON.

### 6.6. Чего temperature не делает

1. **Не добавляет знания.** Если факта нет в весах/контексте, высокая T не «найдёт правду» — скорее увереннее наплетёт.
2. **Не заменяет RAG.** Чтобы опираться на wiki, нужен retrieve; T только влияет на формулировку выбора токенов.
3. **Не равна «точности».** Низкая T → стабильность, не гарантия истины. Можно стабильно повторять ошибку.
4. **Не единственная ручка.** Ещё бывают `top_p` / `top_k` (отсекают хвост кандидатов). На старте достаточно понимать temperature.

### 6.7. Как выбирать в задачах GenAI

| Задача | Temperature | Почему |
|--------|-------------|--------|
| JSON / structured output | 0–0.2 | нужен стабильный формат |
| Ответ по RAG (runbook VPN) | 0–0.3 | меньше фантазий |
| Классификация / маршрутизация тикета | 0–0.2 | нужен повторяемый класс |
| Черновик письма «помягче» | 0.5–0.8 | вариативность формулировок |
| Идеи названий / брейншторм | 0.9–1.3 | разнообразие важнее строгости |

### 6.8. Для бизнеса одной фразой

> Temperature — ручка случайности следующего слова.  
> Ниже — ответы стабильнее и консервативнее.  
> Выше — разнообразнее, но менее надёжно для фактов.

## 7. «Модель не уверена» на пальцах

Softmax дал:

```
класс A: 0.40
класс B: 0.35
класс C: 0.25
```

Победитель A, но отрыв маленький → **модель не уверена**.  
Имеет смысл: спросить человека, показать top-2, не автоэскалировать.

Другой край:

```
A: 0.96
B: 0.03
C: 0.01
```

Уверенность высокая (это всё ещё не гарантия истины — калибровка бывает кривой, но сигнал полезный).

## 9. Шпаргалка для собеса (30–40 сек)

> Softmax переводит сырые баллы модели в вероятности, сумма 1.  
> Temperature управляет остротой этого распределения: ниже — модель стабильнее выбирает самый вероятный вариант, выше — ответы разнообразнее и менее предсказуемы.  
> Для прод-задач вроде JSON и поддержки обычно ставят низкую temperature.

## 11. Критерий «тему понял»

1. Вероятности в сумме 1 для полного набора классов.  
2. Softmax: сырые баллы → доли.  
3. Temperature ↑ → распределение площе.  
4. Редкая серия орлов не «ломает» 0.5 на честной монете.
