## 1. Матрица = таблица чисел

**Вектор** — список чисел (одна строка или столбец):

```
x = [2, 3, 1]    // например: priority=2, words_vpn=3, is_vip=1
```

**Матрица** — таблица из строк и столбцов:

```
A = | 1  0  2 |     // размер 2×3 : 2 строки, 3 столбца
    | 0  1  1 |
```

Говорят «матрица m×n» = m строк, n столбцов.

В ML часто:

- строки = примеры (тикеты);
- столбцы = признаки (фичи).

Аналогия Laravel: `Collection` строк из БД → каждая строка массив полей. Матрица — когда смотрите на всё сразу как на таблицу чисел.

---

## 2. Умножение матрицы на вектор

Зачем: «прогнать» набор признаков `x` через набор весов.

Правило: матрица **(m×n)** × вектор длины **n** → вектор длины **m**.

Каждая **строка** матрицы «скалярно множится» на вектор (как dot из фазы A):

```
строка · x = sum(строка[i] * x[i])
```

### Пример (как задача E1)

```
A = | 1  2  0 |      x = | 3 |
    | 0  1  4 |          | 1 |
                         | 2 |

Первая компонента результата:
  1*3 + 2*1 + 0*2 = 3 + 2 + 0 = 5

Вторая:
  0*3 + 1*1 + 4*2 = 0 + 1 + 8 = 9

Результат: | 5 |
           | 9 |
```

Смысл: две строки = два «фильтра» / два нейрона / два выхода.  
Вход один и тот же `x`, выходов два числа.

Проверка размерностей: 2×3 × 3×1 → 2×1. Если не сходится — ошибка.

---

## 3. Линейная модель: y ≈ w·x + b

Самая простая модель «предсказания числа или балла»:

```
y ≈ w1*x1 + w2*x2 + ... + wn*xn + b
```

или коротко:

```
y ≈ w · x + b
```

| Символ | Смысл | Пример |
|--------|--------|--------|
| `x` | признаки входа | priority, длина текста, есть_ли "vpn" |
| `w` | веса (что выучила модель) | насколько важна каждая фича |
| `b` | bias, сдвиг | базовый уровень без фич |
| `y` | предсказание | балл «срочности» или вероятность до softmax |

Пример на пальцах:

```
x = [priority=3, has_vpn=1]
w = [0.5, 2.0]
b = 0.1

y = 0.5*3 + 2.0*1 + 0.1 = 1.5 + 2 + 0.1 = 3.6
```

Интерпретация: слово про VPN сильно поднимает балл (вес 2.0).

**Линейная** = вклад признаков складывается; нет сложных «если A и B вместе, то магия» внутри самой формулы (это уже деревья/нейросети).

Почему бустинг/деревья часто сильнее на таблицах: ловят нелинейности и взаимодействия фич. Линейная — простой сильный baseline.

---

## 4. Loss «на пальцах»

**Loss (функция потерь)** — штраф за ошибку предсказания.

Идея:

- угадали почти точно → loss маленький;
- ошиблись сильно → loss большой;
- обучение = подкрутить `w` и `b`, чтобы **средний loss на train** стал меньше.

Пример для числа (упрощённо):

```
факт y_true = 5
предсказание y_pred = 8
ошибка = 3
loss ~ (ошибка)^2 = 9   // квадрат сильнее штрафует крупные промахи
```

Для классов (spam / not spam) loss другой по формуле, но смысл тот же: **неправильный класс → большой штраф**.

Аналогия Laravel: в тестах `assertEquals` — либо ок, либо fail. Loss — «насколько сильно fail», непрерывная шкала.

Градиентный спуск (фаза F) = шагать по весам так, чтобы loss уменьшался. Сейчас достаточно идеи штрафа.

## 5. Overfitting

**Overfitting (переобучение)** — модель слишком хорошо подстроилась под train и плохо работает на новых данных.

Классическая аналогия (задача E2):

> Студент выучил билеты **наизусть**.  
> На экзамене вопросы чуть перефразировали — сыплется.

В тикетах:

- на train accuracy 99%;
- на val 71%;
- majority baseline на val 73%.

Модель запомнила странные совпадения train («если id чётный → resolved»), а не смысл.

Признаки overfitting:

- огромный разрыв train vs val;
- очень сложная модель при малом числе примеров;
- метрики «идеальные» только на знакомых строках.

---

## 6. Train / val / test — зачем три набора

Вы уже знали train/val из фазы B. Кратко с test:

| Набор | Роль |
|-------|------|
| **train** | учим / подбираем веса |
| **val** | выбираем модель, гиперпараметры, early stop; можно подглядывать много раз |
| **test** | финальная оценка **один раз**; имитация прода |

Почему нельзя только train (задача E3):

1. Overfitting не заметите — цифры всегда радуют.  
2. Не узнаете, обобщается ли модель.  
3. На собесе/в пилоте «99% на train» не аргумент.

Почему test отдельно от val:

- на val вы много раз крутили настройки → слегка «подогнали» и val;
- test — честный финальный экзамен.

На старте пилота часто хватает train/val; test добавляют, когда уже сравнивают подходы всерьёз.

Связь с leakage: даже идеальный split бесполезен, если в `x` лежит шпаргалка (`closed_at`).

---

## 7. Картинка целиком

```
признаки x  →  линейная модель (w·x + b)  →  предсказание y
                      ↑
              крутим w,b чтобы loss ↓
                      ↑
         только на train; проверяем на val/test
```

В sklearn это примерно:

```
model.fit(X_train, y_train)
model.predict(X_val)
```

Матрица `X` — таблица признаков; вектор `y` — ответы.

---

## 8. Шпаргалка для собеса (40 сек)

> Линейная модель — взвешенная сумма признаков плюс сдвиг.  
> Loss показывает, насколько ошиблись; обучение уменьшает loss на train.  
> Смотреть качество только на train нельзя — будет overfitting.  
> Нужен val (и желательно test). На таблицах часто берут деревья/бустинг сильнее линейной, но линейная — понятный baseline.
